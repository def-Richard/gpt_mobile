# OpenAI 与兼容接口增强功能

本文说明本分支相对上游 0.9.0 新增的功能，适用版本为 0.9.0-2。

## 适用范围

模型目录、推理控制和回复统计面向 OpenAI、Custom、OpenRouter、Groq 与 Ollama。Anthropic、Google 和 LiteRT-LM 保留原有设置，不显示不适用的扩展控件。**Fast 只对类型为 OpenAI 的提供商显示**，使用 Responses 请求的 `service_tier` 参数。

## 配置提供商

1. 在“设置 → 添加提供商”或首次启动向导中选择 API 类型。
2. 填写名称、API 基础地址和密钥。地址须以 `/` 结尾，例如 `https://api.example.com/v1/`，不要附加 `models`、`responses` 或 `chat/completions`。
3. 点击模型框右侧的刷新按钮。应用使用当前地址与密钥访问 `{base_url}models`，读取返回的模型 ID。
4. 从下拉列表选择模型。模型 ID 保留原文，该选择框不接受任意手填内容。
5. 如需推理，开启“深度推理”并选择强度。可先点击“检测”，再保存配置。

已有提供商可在设置中打开模型选择，继续使用已保存的目录，或手动刷新。

### 模型目录的保存与刷新

- 目录保存在对应提供商的数据库记录中，不只是页面内存。
- 不同提供商独立保存目录，即使 API 地址相同也不会相互覆盖。
- 重启、打开模型菜单和切换模型直接读取本地目录，只有手动刷新会更新目录。
- 刷新成功后完整替换旧目录；合法空列表会清空目录并提示没有可用模型。
- 网络或服务错误不会删除旧目录，页面会显示错误并保留原选项。
- 修改名称、推理等无关设置不会覆盖已刷新的目录；修改 API 地址、密钥或协议会清空旧目录，需要重新刷新。
- 删除提供商时，其模型目录随之删除。

旧版本没有保存过的列表无法恢复，升级后需要刷新一次。服务商没有返回上下文容量时，可在“上下文设置”中手动填写。

### 连接检测

“检测”会向当前模型发送一条短请求，检查地址、认证、模型及推理参数能否被服务接受。OpenAI 使用 Responses 接口，兼容类型使用 Chat Completions 接口。

这是真实模型请求，可能消耗少量 token。检测通过不代表该模型支持所有工具、多模态或 Fast 能力。HTTP 错误会在页面中显示；当前密钥若出现在错误正文中，会被脱敏。

## 会话内切换

提供商、模型、推理强度和上下文用量环位于**输入框上方**，键盘展开后仍处于输入框上方。

| 入口 | 操作 |
| --- | --- |
| 提供商名称 | 从已启用的提供商中选择，影响后续发送，保留历史回复及其版本。 |
| 模型名称 | 直接展开本地模型列表，点选即应用；底部“刷新模型”用于更新目录。 |
| 推理强度 | 选择 `low`、`medium`、`high`、`xhigh`、`max`，或选择“默认”以省略强度参数。 |
| 用量环 | 查看最近一次请求的占用和模型窗口容量，进入上下文设置。 |

模型与推理覆盖只作用于当前会话。生成期间暂时禁用切换，避免请求与界面配置不一致。多提供商历史仍可分别查看；重新打开会话时，优先显示实际有回复的列。

## 深度推理

- 提供商的“深度推理”未开启，或会话中选择“默认”：不发送推理强度，使用服务端默认行为。
- 开启并选择强度：OpenAI 发送 `reasoning.effort`，兼容接口发送 `reasoning_effort`。
- 五个档位保留英文协议值。它们是应用提供的选项，不表示每个模型都支持全部档位；可通过连接检测确认。

## OpenAI Fast

OpenAI 模型列表顶部提供默认关闭的 **Fast** 勾选项：

- 主动勾选后发送 `"service_tier": "priority"`。
- 取消勾选后完全省略 `service_tier`，不发送 `null`，也不强制其他服务等级。
- 选择按当前会话中的提供商保存；更换同一提供商的模型后保留选择，其他会话不会自动开启。
- 工具调用后的模型轮次继续使用该选择；上下文压缩生成摘要后，仍能识别实际会话的 Fast 设置。
- 不会向其他类型提供商自动附加该参数。

服务商决定 Fast 的支持情况、处理速度和费用，第三方接口可能拒绝或忽略该参数。参见 [OpenAI Fast mode](https://developers.openai.com/api/docs/guides/priority-processing)。

## 上下文用量

点击用量环可查看已用/剩余百分比、已用 token 和窗口容量。占用基于此模型最近一次有用量反馈的请求，包括该次输入与输出，**不是整段会话的累计计费用量，也不包含草稿**。

窗口容量来自服务商元数据或手动设置。缺少必要数据时显示未知，不编造百分比。

## 回复信息与操作

用户消息显示发送时间。模型回复的第一行紧凑显示：

```text
14:36 · 5s · 172k
```

- 时间使用设备本地时区的 `HH:mm`，点击可查看完整年月日时分秒。
- 耗时按秒、分钟、小时简写，例如 `5s`、`3m`、`1h`。
- 点击 token 查看输入、输出和缓存输入的精确数量。
- 同一回复包含多轮模型调用时，累加已回传的用量。缓存 token 已包含在输入中，不重复计入总数。
- 未回传字段显示 `—`；旧回复不会被补算成精确统计。
- 重新生成使用独立运行记录，切换历史版本时显示对应记录的信息。

第二行是复制、选取文本、编辑、重新生成和必要的版本切换；单版本时隐藏版本切换。第三行仅显示必要的简短提示。字号、图标和间距均已收紧，让正文保持主要视觉层级。

## 升级与数据迁移

包含 Room 数据库 11→12→13 的迁移，新增模型目录、会话推理/Fast 选择及运行用量字段。旧会话、提供商和回复内容保留，新增统计字段为空，Fast 默认关闭。

公开发布包的显示版本是 **0.9.0-2**，内部版本号 **27**。此前本地同名测试包为 26；内部版本号递增后，同签名安装包可作为更新安装。是否能覆盖其他渠道的包还取决于签名，不能只看显示版本。
